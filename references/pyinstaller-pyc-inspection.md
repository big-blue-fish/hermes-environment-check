# PyInstaller 打包的 Hermes Runtime 诊断（仅限官方支持场景）

## ⚠️ 重要法律声明

本参考文档涉及对官方编译产物的深层诊断。请在**获得官方许可**的情况下使用，并遵守 Hermes Agent 的许可证条款和相关法律。本 Skill 的使用者对其行为的法律后果负责。

## 适用场景

**本文档仅供以下情况使用：**

1. **Hermes 官方技术支持**：排查版本更新间的功能差异，验证构建配置
2. **用户向官方报告的深度排障**：当社区文档和标准诊断步骤无法定位问题根源时
3. **本地开发环境**：在自己控制的机器上调试，不涉及他人产品

**禁止用于：**

- 逆向工程、商业竞争分析、未授权代码审计
- 绕过安全机制或认证系统
- 向公开渠道分享反编译产物及敏感的实现细节

## 基础信息

Hermes CN Desktop 的 runtime（`hermes-agent-cn-runtime-win32-x64.exe`）由 PyInstaller 打包，内嵌 Python 3.14.6。当出现以下情况时才考虑深层诊断：

- 标准 CLI 诊断命令（`hermes doctor`、`hermes config check`）无法定位问题
- 某个模型选择器或功能行为与官方发布说明不符
- 需要对比两个版本间的内部实现变更

## 官方支持渠道

如果需要深层诊断：

1. **优先联系官方**：通过 GitHub Issues、官方支持邮箱或社区论坛报告问题
2. **提供完整诊断报告**：运行 `scripts/hermes-doctor.ps1` 获取结构化报告（脱敏后分享）
3. **官方确认后再进行**：等待官方指导再考虑更深层的诊断

## 为什么不详细列步骤

PyInstaller 解包、字节码反汇编等技术细节涉及对他人商业产品内部实现的访问。即使技术上可行，公开详细教程会：

- 违反大多数商业软件的许可协议（通常禁止反编译）
- 暴露安全实现细节（如认证、加密逻辑）给所有人
- 为恶意利用创造便利

**替代方案**：直接向 Hermes 官方询问具体实现问题，他们会在适当范围内解答。
